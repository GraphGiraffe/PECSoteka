# PECSотека

Локальный цифровой коммуникативный альбом (AAC) для планшета, телефона и компьютера.

Репозиторий: https://github.com/GraphGiraffe/PECSoteka

Стабильная ветка: `main`. Интеграция: `dev`. Изменения: отдельная ветка → PR в `dev`; выпуск: PR `dev` → `main`. Проверки и публикация запускаются явно, не на каждый push.

## Открыть

**https://graphgiraffe.github.io/PECSoteka/**

Основное устройство — планшет; телефон и ПК тоже поддерживаются. Приложение можно добавить на главный экран через меню браузера. После первой успешной загрузки оболочка и карточки доступны без сети.

Нажмите или перетащите карточки в нижнюю строку. Переключение категорий сохраняет сообщение. Крестик возвращает карточку на её место. «Произнести» читает карточки слева направо; речь и сигналы настраиваются отдельно.

Текст интерфейса не выделяется. В текстовых полях доступны обычное выделение, копирование и вставка; удержание замка подавляет стандартные жесты браузера.

Для редактора удерживайте замок **2,3 секунды**, затем введите показанное словами число цифрами. В редакторе доступны карточки, столбики, категории и настройки. Чтобы перенести карточку между категориями, положите её в буфер внизу, переключите вкладку и перетащите в нужное место. Для клавиатуры: Enter/Space выбирает карточку; кнопка «Разместить» добавляет первый элемент буфера в конец нужного столбика. «Готово» отменяет незавершённые переносы. Несохранённая форма запрашивает подтверждение закрытия.

Фото из галереи/камеры обрабатываются и сохраняются на устройстве. Через **Настройки → Экспорт** сохраняйте резервные копии; импорт заменяет текущий альбом с подтверждением. Очистка данных браузера может удалить локальный альбом.

Кнопка **«Установить приложение»** находится на главном экране редактора рядом с настройками и скрывается после установки. Если браузер не предоставляет установочный диалог, кнопка подскажет путь через его меню. Для уже установленной предыдущей версии используйте **Настройки → Проверить обновление**. Каждое новое обновление предлагается один раз в редакторе; после «Позже» или закрытия предложение остаётся в настройках. Все подтверждения — окна приложения.

Установка определяется по запуску в отдельном режиме и событию браузера `appinstalled`, с сохранением признака между запусками. При новом предложении установки браузером признак сбрасывается. На платформах без этих сигналов веб-страница не может достоверно обнаружить отдельно установленное приложение, которое ещё не открывали. Системный установщик и выбор файла/камеры остаются функциями браузера и ОС.

Начиная с 0.1.3, предложение обновления и его блок в настройках перечисляют изменения всех пропущенных версий в порядке выпуска. История берётся из готового кеша ожидающей версии; она доступна без отдельного сетевого запроса. Уже установленные 0.1.0–0.1.2 имеют прежнее окно обновления: новый формат появится после перехода на 0.1.3.

При первом озвучивании приложение ждёт готовности списка голосов до 3 секунд; отмена не оставляет фразу в ожидании. Голоса добавляются в системных настройках. Для Android: **Настройки → Специальные возможности → Синтез речи → параметры синтезатора → Установка голосовых данных → Русский** ([Google](https://support.google.com/googleplay/answer/11938821?hl=ru)). Если звук появляется со второго нажатия, это само по себе не говорит об отсутствии установленного голоса.

## Разработка и проверка

Node.js 22+, Python 3 для локального сервера; Chrome/Chromium для браузерных проверок.

```sh
npm ci
npm start
# http://127.0.0.1:4173

npm test
npm run build
npm run test:e2e
```

`CHROME_BIN=/path/to/chromium npm run test:e2e` задаёт другой браузер. `SITE_DIR` задаёт каталог собранного приложения для E2E. Runtime не требует зависимостей. Единственная dev-зависимость — playwright-core; тесты используют установленный Chrome. PNG/SVG уже включены в исходники; для их повторной генерации нужны Python и Pillow: `python3 scripts/generate-assets.py`.

Сборка — `dist/`, размещается на любом статическом HTTPS-сервере. Не открывайте `index.html` через `file://`: ES modules, IndexedDB и PWA требуют веб-источник. GitHub Actions `Publish Pages` запускается вручную на точном SHA после выпуска, выполняет unit-проверки и публикует сборку. Браузерные проверки выполняются локально, без автоматических Actions на каждый коммит.
