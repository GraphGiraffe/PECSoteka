# Проверка 0.1.2

26 октября 2026, Node.js 22, Chromium/Google Chrome на Linux с touch-контекстом. Сборка `dist/`, cache ID `68e1e4a40dcd`.

До исправления новый сценарий `npm run test:e2e` завершался ошибкой: у `.brand` значение `user-select` было `auto`, а не `none`. В исходниках блокировка распространялась на карточки, рабочую область и задание взрослого, но не на весь интерфейс. Отказ входа на исходном пользовательском устройстве не воспроизведён и не объявляется доказанным следствием выделения.

После исправления:

- `npm test`: 12/12.
- `npm run build`: успешно, 50 ресурсов и `.nojekyll`.
- `npm run test:e2e`: 20/20. Новая регрессия проверяет запрет выделения в шапке, вкладках, заголовке, подписях карточек и замке; отмену `selectstart` и `contextmenu` вне полей; открытие проверки взрослого настоящим touch-удержанием 2,4 секунды; выделение четырёх символов в поле ответа и сохранение событий выделения/контекстного меню внутри него.
- Сохранены проверки карточек, защищённого редактора, panning, резервных копий, встроенных подтверждений и настоящего применения waiting service worker.

Для Safari добавлены `-webkit-user-select` и `-webkit-touch-callout`, для замка — `touch-action:none` и подавление стандартного действия `pointerdown`. Работа на конкретном Android/iPadOS требует проверки на нём; исходное объяснение сбоя остаётся гипотезой.
