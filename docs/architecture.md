# Архитектура 0.1

Приложение не требует backend или аккаунта. В production нет npm-зависимостей, аналитики, внешних шрифтов и библиотек пиктограмм. ES modules работают в современных браузерах. TypeScript и UI-фреймворк из рекомендуемой архитектуры ТЗ для первого небольшого статического выпуска не потребовались.

| Модуль | Ответственность |
|---|---|
| `domain.js` | Альбом, адреса карточек, чистая операция перемещения, проверки формата, числа прописью |
| `storage.js` | Версионированная IndexedDB, транзакции альбома и Blob, экспорт/импорт |
| `drag.js` | Pointer Events, зоны сброса, захват указателя, предпросмотр, отмена и возврат |
| `pwa.js` | Признак установки, ожидающий worker, идентификатор обновления и однократное предложение |
| `services.js` | Локальные сигналы Web Audio, системная речь, сжатие и кадрирование фотографий |
| `app.js` | Режимы, формы редактора, коммуникативная строка, проверка взрослого, настройки |
| `sw.js` | Кеш целой версии оболочки и стартовых изображений, явное обновление |

## Состояние

`album` — единственное постоянное дерево. `communication` — временные экземпляры со стабильными ID и адресами источника. `buffer` — только временные `pendingMove` редактора. `DragController.drag` — чисто визуальное состояние жеста. Вход в редактор сохраняет сообщение отдельно; буфер его не подменяет.

При выборе карточки её ID остаётся на прежнем месте в постоянном дереве; UI показывает контур. Возврат отменяет временный экземпляр. При успешной правке редактор создаёт копию дерева, выполняет вставку со сдвигом и сохраняет всё одной IDB-транзакцией. До её завершения UI не подтверждает операцию. При нехватке места или конфликте revision старый альбом остаётся целым. Незавершённый перенос никогда не записывается, поэтому перезагрузка открывает режим общения без потерянных карточек.

Если взрослый меняет расположение карточки, которая присутствует в сохранённом на время редактора сообщении, её экземпляр получает новый постоянный домашний адрес. Другие элементы сообщения сохраняют порядок. Несколько открытых вкладок не перезаписывают правки друг друга: устаревшая запись отклоняется, требуется перезагрузка старой вкладки.

## Медиа и резервная копия

Фото из файла или камеры декодируется локально, обрезается и повторно кодируется в JPEG 768×768. EXIF исходного файла в новый JPEG не переносится. Blob хранится отдельно от JSON альбома. При копировании карточки можно разделять один Blob; сборка мусора удаляет фото только после исчезновения последней ссылки.

Экспорт — один JSON-файл формата `pecsoteka`, версии 2, включающий манифест, встроенные base64-изображения и озвучки WAV. Импорт проверяет версию, адреса, уникальность, допустимые настройки, типы/размеры фото до замены текущих данных. Ограничение копии — 100 МБ, отдельных исходных фото — 20 МБ. PIN в 0.1 не реализован и не экспортируется.

## PWA

Все пути относительные: приложение работает в корне и в `/PECSoteka/`. При сборке кеш получает хеш содержимого оболочки. Одна активная версия обслуживает и HTML, и JS, чтобы не смешивать версии. Новая версия ждёт явного применения взрослым в настройках. Фото находятся в IndexedDB и не входят в серверный кеш. Первое открытие требует сети и HTTPS (для localhost допустим HTTP).

## Визуальные решения

Референсы задают пять вертикальных направляющих, крупные карточки, полосу цветных вкладок над строкой и озвучивание справа. Из PlayRoom переосмыслены базовые цвета (`paper`, `ink`, `green`, `lime`, `coral`), скругления и спокойная обратная связь. Код игрового runtime, ассеты паков, авторизация и сетевые зависимости не переносились. 36 стартовых SVG нарисованы для этого проекта в `scripts/generate-assets.py`, без внешних библиотек и фотографий. Это демонстрационные иллюстрации, не стандартизованный словарь AAC.

Все вкладки всегда имеют собственный цвет. Фон рабочей области берёт тот же цвет категории в более мягком оттенке; активная вкладка выделяется дополнительным тёмным контуром. Взрослый может менять цвет категории в редакторе.

По умолчанию речь выбирает только локальный русский голос. Сетевой системный голос используется лишь после явного выбора взрослым в настройках.

## Изменения 0.1.1

Признак установки определяется по standalone и событию `appinstalled`; локальная метка сохраняется между запусками. Новое `beforeinstallprompt` снимает старую метку после удаления приложения. Нативные ограничения детекции перечислены в README.

Ожидающий service worker сообщает свой cache ID через MessageChannel. Для каждого ID предложение обновления показывается один раз и только взрослому, когда не открыта форма и не идёт жест. После закрытия предложение доступно в настройках; метка показа не относится к данным альбома. Новый worker активируется только по явной команде обновления.

Подтверждения используют отдельное стилизованное HTML-окно поверх основной формы, не уничтожая её состояние. Прокрутка свободной зоны вкладки и заголовка изменяет `scrollLeft/scrollTop` только области карточек; жесты самих карточек по-прежнему обрабатывает DragController.

## Изменения 0.1.3

Speech запускает обнаружение голосов заранее. Если подходящий голос ещё не готов, запрос ждёт `voiceschanged` и выполняет ограниченные проверки для движков без события; общий предел — 3 секунды. Токен запроса и отмена ожидания предотвращают воспроизведение устаревшей фразы. Когда голос уже доступен, вызов `speak` остаётся синхронным внутри пользовательского действия. Сетевой голос автоматически не выбирается.

`updates.json` входит в кеш версии. Ожидающий worker передаёт через `GET_VERSION` свой appVersion и историю выпусков вместе с cache ID. `releasesBetween` выбирает только версии новее установленной и не новее ожидающей, сортирует их численно. UI экранирует тексты и показывает одинаковую историю в предложении и настройках. Старые установленные интерфейсы не подменяются; новый формат доступен в интерфейсе 0.1.3 и следующих версий.


## Озвучки и совместимость 0.2.0-preview.1

`audio.js` нормализует захваченные MediaRecorder или загруженные записи в mono
PCM WAV 22050 Hz. Лимиты: исходный файл 20 МБ, озвучка 30 секунд, сохранённый Blob
до 4 МБ. Проигрывание использует Web Audio; последовательность чередует записи
и завершившиеся сегменты системной речи. Отмена инвалидирует ожидание и
декодирование; громкость общая с речью. Частные Blob не отправляются на сервер.

`recording-editor.js` владеет микрофоном и двумя кандидатами записи. Изменение
выбора не меняет IndexedDB. При сохранении передаётся только выбранный новый Blob;
выбор исходного оставляет прежний audioId. Закрытие формы и уход со страницы
освобождают захват, включая запоздалый ответ на запрос разрешения.

IndexedDB версии 2 сохраняет прежние `album` и `images`, добавляя `recordings`.
Валидация переводит альбом схемы 1 в 2 без потери фотографий и домашних адресов.
`AlbumRepository.save` записывает дерево, фото и озвучки одной транзакцией с
проверкой revision; недостающая аудиоссылка откатывает транзакцию. Сборка мусора
учитывает ссылки всех карточек, включая копии.

Резервная копия версии 2 содержит `recordings` с data URI WAV, максимум 100 МБ.
Импорт продолжает читать версию 1; новые копии с аудио старый выпуск не читает.
Фото и аудио проверяются до замены текущего альбома.

`npm run build -- --preview` создаёт отдельный manifest ID `/pecsoteka-preview`,
базу `pecsoteka-preview`, префикс метаданных `pecsoteka-preview-` и такой же
префикс service-worker caches. Исходники production не переключают свои имена
хранилищ; переписывается только сгенерированный `dist/config.js`. Маршрут Funnel
ограничен отдельным каталогом готовой сборки.
