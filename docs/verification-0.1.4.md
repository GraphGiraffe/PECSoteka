# Проверка 0.1.4

27 октября 2026. Node.js 22, Chromium на Linux. Проверялась сборка `dist/`,
cache ID `fa2340db8b91`.

- `npm test`: 21/21.
- `npm run build`: успешно; 56 ресурсов плюс `.nojekyll`. В сборку входят LICENSE,
  PERMISSIONS.md, THIRD_PARTY_NOTICES.md и уведомления Playwright. Текст лицензии
  и разрешения включён без преобразований.
- `npm run test:e2e`: 22/22. Новая проверка читает результат Chromium
  `Page.getAppManifest`: `manifest.id` равен origin + `/pecsoteka`, а `startUrl`
  и `scope` равны адресу каталога `/PECSoteka/`. Это проверка реального разрешения
  manifest браузером, без имитации алгоритма идентичности.
- Проверки обновления, сохранения альбома, фотографий, резервной копии и офлайн-кеша
  прошли. Тестовые будущие версии в сценарии ожидающего service worker сдвинуты
  на 0.1.5 и 0.1.6, чтобы установленная 0.1.4 исключалась из списка изменений.

Состав `dev` до подготовки релиза проверен: PR #18 добавляет только отдельный ID
и документацию, других изменений приложения относительно `main` не было.
Лицензионные файлы уже были в `main`, но ещё не входили в опубликованную 0.1.3.

На момент проверки опубликованные PlayRoom, ROADMAPler и PECSотека содержали
`id: "./"`, разрешающийся в корневой адрес общего origin. Публикация этого
репозитория обновляет только PECSотеку. Релизы соседних проектов выполняются
отдельно.

IndexedDB, её версия, имена кешей и ключей пользовательских данных не переименованы.
Смена установочного ID сама по себе не разделяет хранилище origin. Нативная
миграция существующих установок на Android/iPadOS и устройствах пользователя
в этой проверке не воспроизводилась. Порядок безопасной переустановки описан в
[PWA-IDENTITY.md](PWA-IDENTITY.md).
