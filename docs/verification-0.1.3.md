# Проверка 0.1.3

26 октября 2026. Node.js 22 и Chromium на Linux. Проверялась сборка `dist/`, cache ID `c5c41c3e989b`.

До исправления `node --test tests/services.test.mjs` воспроизводил ошибку первого запроса: при пустом списке голосов `Speech.say` немедленно бросал исключение, не ожидая асинхронной готовности движка. Это соответствует наблюдаемому симптому, но конкретное Android-устройство не подключалось. API предоставляет событие [`voiceschanged`](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/voiceschanged_event) для изменения списка.

- `npm test`: 21/21. Шесть сценариев речи проверяют первое ожидание, немедленный вызов при готовом голосе, движок без события, отмену, замену запроса и отсутствие неявного выбора сетевого голоса. Три сценария истории проверяют все пропущенные версии, числовой порядок (включая 0.1.9 → 0.1.10), границы и некорректные записи.
- `npm run build`: успешно; 51 ресурс плюс `.nojekyll`.
- `npm run test:e2e`: 21/21. Браузерный сценарий меняет пустой список голосов на готовый через событие с задержкой: одна кнопка запускает речь один раз без ложного сообщения. Это проверка адаптера, не физического динамика.
- Настоящий waiting service worker передаёт историю двух следующих тестовых версий. Окно предложения и блок в настройках показывают обе в порядке выпуска. Уже установленная версия исключается; закрытие, повторный вход и применение обновления сохраняют прежнее поведение и данные альбома.

История поставляется из кеша ожидающей версии, а не из кеша установленного интерфейса. В установленном 0.1.2 остаётся старый интерфейс предложения; новый формат применяется после установки 0.1.3. Голоса и их установка зависят от ОС и браузера; инструкция Android в настройках опирается на [справку Google](https://support.google.com/googleplay/answer/11938821?hl=ru).
